# Delegate

作業を分けるかどうか、分けるなら何で分けるかを決めて、親として最後まで管理する。

## 使い分け

上から順に当てはめ、最初に当てはまったものを選ぶ。選んだ理由を一言添えてユーザーに伝えてから始める。

| # | 状況 | 手段 |
|---|---|---|
| 1 | 互いに依存する、または同じファイルを触る | 分けない。自分が順に進める |
| 2 | 1 つの難しい問題を深く考えたい | 分けない。effort を上げるようユーザーに勧める |
| 3 | 読むだけで結論が欲しい（調査・探索・レビュー） | サブエージェント（Agent ツール） |
| 4 | 書き込みを伴う独立した作業が複数ある／長くかかる／途中で人が承認・修正したい／別の種類のエージェントに頼みたい | herdr のペイン + worktree（下の手順） |

迷ったら軽い方（番号の小さい方）を選ぶ。herdr の子は 1 体ずつ丸ごとのセッションなので、トークンも人の注意も多く使う。

## herdr のペインに任せる手順

前提: `test "${HERDR_ENV:-}" = 1` が通ること。通らなければ herdr の中ではないと伝え、3 か 1 に切り替える。
コマンドの書き方は herdr スキル（`herdr --skill` と同じ内容）に従う。ユーザーがこのスキルで手順 4 を選んだことは、
herdr スキルが求める「ユーザーが herdr・worktree を明示した」に当たる。
herdr は `&&` や `;` でほかのコマンドとつながず、1 回の Bash で単独に実行する
（sandbox の `excludedCommands` に当たらず、ソケットにつながらなくなる）。

1. **分ける**: タスクに分け、互いに同じファイルを触らないことを確かめる。子は同時に 3 体まで。
   それぞれに、名前（`[a-z][a-z0-9_-]*`、例: `feat-login`）とブランチ名を決める。
2. **worktree を作る**: タスクごとに `herdr worktree create --cwd <リポジトリ> --branch <ブランチ> --no-focus`。
   ID は応答の JSON から読む（推測しない）。
3. **起動する**: worktree の root pane で `herdr agent start <名前> --kind claude --pane <pane_id>`。
   `agent_not_ready` が返ったら、新しいディレクトリの trust 確認などで止まっている。
   自分では答えず、ユーザーに `prefix+alt+1` で対応してもらってから続ける。
4. **頼む**: `herdr agent prompt <名前> "<依頼>"` を `--wait` 付きで、Bash の `run_in_background` で実行する。
   依頼文は単独で読んで分かるように書く: 目的、触ってよい範囲、完了の条件、
   「このブランチにコミットして終える。push とマージはしない」。
   複数の子を待つときも、1 体ずつ別のバックグラウンド実行にする（終わった順に自分が起こされる）。
5. **待つ**: 待っている間はユーザーとの会話を続けてよい。起こされたら `herdr agent get` で状態を見る。
   - `blocked`: 承認や質問で止まっている。**自分では答えない**（`agent send-keys` で承認しない）。
     `herdr agent read` で内容を確かめ、子の名前と何を聞かれているかをユーザーに伝える。
     ユーザーが対応したら、`herdr agent wait <名前>` をまたバックグラウンドで実行する。
   - `timeout` や `agent_prompt_stalled`: 届かなかったとは限らない。`agent read` で確かめ、同じ依頼を送り直さない。
6. **受け取る**: `idle` / `done` になったら、`herdr agent read <名前> --source recent-unwrapped` で報告を読み、
   worktree の `git log` と `git diff <base>...HEAD` を見る。差分のレビューはサブエージェントに任せてよい。
7. **報告する**: 子ごとに、結果・レビューの指摘・次にすべきこと（マージしてよいか）をまとめて伝える。
8. **片付ける**: マージや worktree の削除（`herdr worktree remove`）は、ユーザーの了承を得てから行う。
   自分が作っていない workspace・タブ・ペインは閉じない。

## 親の役目

- 子の worktree のファイルを自分で書き換えない。直してほしいところは、その子に `agent prompt` で頼む。
- 子どうしの調整（片方の結果をもう片方に渡すなど）は自分が仲立ちする。
- `herdr pane run` / `pane send-text` / `pane send-keys` は、ユーザーに頼まれたときだけ使う。
